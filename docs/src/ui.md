# `src/ui.ts` — Event wiring, tools, theme, shortcuts

Wires every DOM event listener and owns the interaction model: tool switching, canvas pointer handling (place/select/drag/connect/pan), the theme toggle, and global keyboard shortcuts.

## Key exports

- **`setupUI()`** — called once from `app.ts`. Calls `setupRibbon()` and attaches all listeners: a delegated handler for ribbon buttons (`data-action`/`data-theme-id`), the drawing tools (`data-tool`), the **Topologies `<select>`** (`#topologySelect` → `loadTopology`, resets to its placeholder) and the **Scenarios flyout menu** (`#scenarioMenuButton` opens the body-level `#scenarioMenu`; group rows fly out per-category submenus, a leaf click → `loadScenario`; closes on outside-click/Escape), canvas pointer/wheel events (double-click a device → configure, double-click a link → toggle its admin status via `toggleLinkShutdown`), the terminal/console inputs, the **dock** (tab-strip clicks/close buttons, the drag-resize handle, the sim-log Packets/Events toggle, and packet-row clicks — a row opens the frame breakdown and pauses the sim), the inspector resize handle, the sim controls, and the global keydown handler.
- **`updateCoordReadout(world)` / `syncCoordReadout()`** — the bottom-right `#coordReadout`: cursor world coords (from pointermove) + the selected device's coords. `syncCoordReadout` is a registry callback so selection changes refresh it.
- **`setTool(tool)`** — switch the active tool (`select`/`computer`/`server`/`switch`/`managed-switch`/`router`/`firewall`/`connect`/`configure`), update button states, the ribbon status line (`#modeLabel` — which also carries transient feedback from imports, link guards, and first-boot outcomes), and the cursor, then re-render. Calls `syncToolGroups` first so the active variant shows on its split-button face. Exposed to `devices.ts` via the device-callback bridge.
- **`syncToolGroups(tool)`** (internal) — when a grouped variant becomes active (face click, menu pick, or keyboard shortcut), the owning split button (Computer / Switch / Security / Legacy) adopts that variant's icon + `data-tool` and marks its menu item; tools outside a group leave the faces alone, so each group remembers its last choice. The caret/menu wiring (open, anchor the `position: fixed` menu, pick, close on outside-click/Escape) lives in `setupUI`.
- **Connect tool** (canvas pointer handler) — click one device, then another to cable them. The default click **auto-picks the first free port** on each end (`addLink` resolves them, no dialog); **Shift-clicking** the second device opens the manual port picker (`openPortSelectionModal`) instead. A reject (e.g. a single-NIC host already cabled) surfaces its reason on `#modeLabel`.
- **`setTheme(id)` / `toggleTheme()`** — switch the colour theme. Themes are a named registry (`THEMES` in `state.ts`): **Warm Light** (default), **Dark**, **Blueprint**. `setTheme` validates the id (with `light` kept as a back-compat alias for `warm-light`, and an unknown id falling back to the default), writes it to the `<html data-theme>` attribute, highlights the matching ribbon button, **clears the `cssColor` cache** (so themed canvas colours refresh), and re-renders. `toggleTheme` cycles to the next theme in the registry. The app boots in **Warm Light** (`initialiseApp` calls `setTheme("warm-light")`). The three theme buttons carry `data-theme-id` and are handled by the delegated ribbon click handler.
- **`openAbout()` / `closeAbout()`** — the Help → About modal. `openAbout` resets any drag offset so the modal re-centres each time. The modal is **draggable** by its header (`startAboutDrag`/`moveAboutDrag`/`endAboutDrag` via pointer capture, clamped to the viewport) and dismissable via the close button, a backdrop click, or Escape. Modals use a solid per-theme `--modal-bg` background.
- **`openSettings()` / `closeSettings()`** — the **Settings** pane, opened by the cog button on the Main tab (`data-action="open-settings"`). Not a modal: it's a right-docked pane (`.settings-pane`) that shares the inspector's grid cell (column 2, row 2) and reuses its look. The functions just toggle a `body.settings-open` class — the CSS forces the two-column layout (even when the inspector is closed), shows the pane, hides the inspector underneath until it closes, and offsets the dock; both functions `requestAnimationFrame(resizeCanvas)` so the stage reflows. Dismissable via the close button or Escape (no backdrop — a pane, not a dimmed overlay). It hosts the global simulation toggles — Auto-DHCP and APIPA fallback (`optAutoDhcp`/`optApipa`, both off by default, still wired once through `bindOptionToggle` → `state.options`, since the inputs are static markup inside the always-present pane).
- **`handleGlobalKeydown(event)`** — the global keyboard handler (extracted from `setupUI` so it can be unit-tested):
  - `Ctrl/Cmd+Z` → undo; `Ctrl/Cmd+Shift+Z` / `Ctrl/Cmd+Y` → redo.
  - `Escape` → cancel an open port-selection modal, else blur the focused field and revert to the select tool. Handled **before** the input guard so it works even while typing in a field.
  - `Delete`/`Backspace` → delete the selected device or link; `V/C/E/S/R/F/H/L/W` → tool shortcuts (select/computer/server/switch/router/firewall/hub/connect/configure). These are suppressed while a text input/select/textarea is focused.
- **`pointerFromEvent`, `bindOptionToggle`** — internal helpers for pointer math and display-option checkboxes.

## How it fits

`ui.ts` is the bridge between raw browser events and the app: it reads pointer positions (via `canvas.ts` transforms), calls `devices.ts` for hit-testing and CRUD, mutates `state` (selection, drag, pan), and calls `render()`/`syncPanel()` to reflect changes. It depends on most other modules but is depended on only by `app.ts` (directly) and `devices.ts` (via the callback bridge), keeping the graph acyclic.

## Notes

- `handleGlobalKeydown` is registered by reference in `setupUI`, so the live handler and the unit-tested function are identical.
- Ribbon buttons are wired by a single delegated click handler over `data-action`/`data-theme-id`; the drawing tools use `data-tool`; built-in topologies load from the File-tab `<select>`, and scenarios from the `#scenarioMenu` flyout. Tab switching lives in [ribbon.ts](ribbon.md).
