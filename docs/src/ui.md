# `src/ui.ts` — Event wiring, tools, theme, shortcuts

Wires every DOM event listener and owns the interaction model: tool switching, canvas pointer handling (place/select/drag/connect/pan), the theme toggle, and global keyboard shortcuts.

## Key exports

- **`setupUI()`** — called once from `app.ts`. Calls `setupRibbon()` and attaches all listeners: a delegated handler for ribbon buttons (`data-action`/`data-theme-id`), the drawing tools (`data-tool`), the **Topologies `<select>`** (`#topologySelect` → `loadTopology`, resets to its placeholder) and the **Scenarios flyout menu** (`#scenarioMenuButton` opens the body-level `#scenarioMenu`; group rows fly out per-category submenus, a leaf click → `loadScenario`; closes on outside-click/Escape), canvas pointer/wheel events (double-click a device → configure, double-click a link → toggle its admin status via `toggleLinkShutdown`), the terminal/console inputs, the **dock** (tab-strip clicks/close buttons, the drag-resize handle, the sim-log Packets/Events toggle, packet-row clicks — a row opens the frame breakdown and pauses the sim — and the packet-list **display-filter** controls: the expression input, the device `<select>`, the protocol chips, and Clear, all driving `state.dock.logFilter` via `clearLogFilter`/`syncSimLog`), the inspector resize handle, the sim controls (the Main-tab ribbon buttons **and** the floating on-canvas transport pill `#simControls`, both via the shared `handleSimPlayPause`), the **device context menu** (right-click a device → `openDeviceContextMenu`: Terminal/Configure/Power/Delete at the cursor, dismissed on outside-click/Escape/wheel), and the global keydown handler. A terminal/console **`Ctrl+C`** (`interruptSimOnCtrlC`) cancels a running sim; the scenario banner's titlebar control **collapses** it to a progress pill (`collapseScenario`/`expandScenario`, the pill ✕ → `dismissScenario`).
- **`updateCoordReadout(world)` / `syncCoordReadout()`** — the bottom-right `#coordReadout`: cursor world coords (from pointermove) + the selected device's coords. `syncCoordReadout` is a registry callback so selection changes refresh it.
- **`setTool(tool)`** — switch the active tool (`select`/`computer`/`server`/`switch`/`managed-switch`/`router`/`firewall`/`connect`/`configure`), update button states, the ribbon status line (`#modeLabel` — which also carries transient feedback from imports, link guards, and first-boot outcomes), and the cursor, then re-render. Calls `syncToolGroups` first so the active variant shows on its split-button face. Exposed to `devices.ts` via the device-callback bridge.
- **`syncToolGroups(tool)`** (internal) — when a grouped variant becomes active (face click, menu pick, or keyboard shortcut), the owning split button (Computer / Switch / Security / Legacy) adopts that variant's icon + `data-tool` and marks its menu item; tools outside a group leave the faces alone, so each group remembers its last choice. The caret/menu wiring (open, anchor the `position: fixed` menu, pick, close on outside-click/Escape) lives in `setupUI`.
- **`handleCanvasPointerDown(event)`** — a press on the canvas, by the armed tool: place, connect, configure, pick a packet, select, drag or pan. A named export registered by reference in `setupUI` (like `handleGlobalKeydown`), so tests drive it with event-shaped objects. It records the press position in `state.pointer` first — a mouse always moves there before pressing, but a touch or a scripted click does not, and the placement ghost and the connect rubber band are drawn at `state.pointer`.
- **Place mode** — with a placement tool armed (`PLACEMENT_TOOLS`), the canvas draws a translucent **ghost** of the device a click would drop under the cursor (`drawPlacementGhost` in [canvas.md](canvas.md)); `pointermove` and `pointerleave` re-render so it follows the cursor and disappears off the canvas. **Only the primary button places** (`isSecondaryPress(event, platform?)` — middle, right, or Ctrl+click on a Mac, where that is the secondary click), and the tool **stays armed** so several devices can be dropped in a row. **Right-click or Escape leaves place mode**: `handleCanvasContextMenu(event)` — the canvas `contextmenu` handler — returns to the select tool and opens **no** device menu while a placement tool is armed (the click that leaves place mode must not also act on what was under it); otherwise it opens the device context menu as before. The cancel is on `contextmenu` rather than `pointerdown` because every platform fires it for a right-click, on press (macOS/Linux) or on release (Windows). `setTool` appends `PLACEMENT_HINT` ("click to place, right-click or Esc to stop") to the status line for placement tools, so the way out is on screen for as long as the tool is armed.
- **Connect tool** (canvas pointer handler) — click one device, then another to cable them. The default click **auto-picks the first free port** on each end (`addLink` resolves them, no dialog); **Shift-clicking** the second device opens the manual port picker (`openPortSelectionModal`) instead. A reject (e.g. a single-NIC host already cabled) surfaces its reason on `#modeLabel`.
- **Port picker** (`src/port-picker.ts`) — the Shift-click dialog: `openPortSelectionModal(fromId, toId)` builds `state.portSelection` from `buildPortList` for each end (a router end lists only the kind of port the cable will use), `syncPortSelectionModal` renders the columns and wires the option clicks, `confirmPortSelection` calls `addLink` with the chosen pair, `cancelPortSelection` closes it. While it is open undo and redo are paused (`undoBlockReason`, with the reason on the status line) and the bare-key shortcuts are off, so the two devices it names cannot be deleted or undone away behind it; `syncPortSelectionModal` closes the dialog if the selection is gone (a restore, a load) or one of its devices no longer exists (review R31). It auto-links pairs with nothing to choose (host↔host, wireless, a rejected pairing). `ui.ts` wires its Confirm/Cancel/backdrop.
- **`setTheme(id)` / `toggleTheme()`** — switch the colour theme. Themes are a named registry (`THEMES` in `state.ts`): **Warm Light** (default), **Dark**, **Blueprint**. `setTheme` validates the id (with `light` kept as a back-compat alias for `warm-light`, and an unknown id falling back to the default), writes it to the `<html data-theme>` attribute, highlights the matching ribbon button, **clears the `cssColor` cache** (so themed canvas colours refresh), and re-renders. `toggleTheme` cycles to the next theme in the registry. The app boots in **Warm Light** (`initialiseApp` calls `setTheme("warm-light")`). The three theme buttons carry `data-theme-id` and are handled by the delegated ribbon click handler.
- **`openAbout()` / `closeAbout()`** — the Help → About modal. `openAbout` resets any drag offset so the modal re-centres each time. The modal is **draggable** by its header (`startAboutDrag`/`moveAboutDrag`/`endAboutDrag` via pointer capture, clamped to the viewport) and dismissable via the close button, a backdrop click, or Escape. Modals use a solid per-theme `--modal-bg` background.
- **`openSettings()` / `closeSettings()`** — the **Settings** pane, opened by the cog button on the Main tab (`data-action="open-settings"`). Not a modal: it's a right-docked pane (`.settings-pane`) that shares the inspector's grid cell (column 2, row 2) and reuses its look. The functions just toggle a `body.settings-open` class — the CSS forces the two-column layout (even when the inspector is closed), shows the pane, hides the inspector underneath until it closes, and offsets the dock; both functions `requestAnimationFrame(resizeCanvas)` so the stage reflows. Dismissable via the close button or Escape (no backdrop — a pane, not a dimmed overlay). It hosts the global simulation toggles — Auto-DHCP and APIPA fallback (`optAutoDhcp`/`optApipa`, both off by default, still wired once through `bindOptionToggle` → `state.options`, since the inputs are static markup inside the always-present pane).
- **`handleGlobalKeydown(event)`** — the global keyboard handler (extracted from `setupUI` so it can be unit-tested):
  - While the tutorial is playing (`state.tutorialActive`) the handler does nothing except swallow Ctrl/Cmd+Z/Y and put `undoBlockReason()` on the status line — see [tutorial.md](tutorial.md).
  - `Ctrl/Cmd+Z` → undo; `Ctrl/Cmd+Shift+Z` / `Ctrl/Cmd+Y` → redo — or, while `undoBlockReason()` is non-null (the port dialog is open), the reason on the status line and nothing else.
  - `Escape` → cancel an open port-selection modal, else blur the focused field and revert to the select tool. Handled **before** the input guard so it works even while typing in a field.
  - `Delete`/`Backspace` → delete the selected device or link; `V/C/E/S/R/F/H/L/W` → tool shortcuts (select/computer/server/switch/router/firewall/hub/connect/configure). These are suppressed while a text input/select/textarea is focused, **while Ctrl, Cmd or Alt is held** (the key is then a browser or OS shortcut: Ctrl+C on text selected in the packet list or a terminal's scrollback copies, it does not arm the Computer tool), and **while a modal dialog is open** (`modalDialogOpen` — the Guide, About or the port picker: Delete behind the Guide used to delete the selected device). Review R44.
- **`pointerFromEvent`, `bindOptionToggle`** — internal helpers for pointer math and display-option checkboxes.

## How it fits

`ui.ts` is the bridge between raw browser events and the app: it reads pointer positions (via `canvas.ts` transforms), calls `devices.ts` for hit-testing and CRUD, mutates `state` (selection, drag, pan), and calls `render()`/`syncPanel()` to reflect changes. It depends on most other modules but is depended on only by `app.ts` (directly) and `devices.ts` (via the callback bridge), keeping the graph acyclic.

## Notes

- `handleGlobalKeydown`, `handleCanvasPointerDown` and `handleCanvasContextMenu` are registered by reference in `setupUI`, so the live handlers and the unit-tested functions are identical (`tests/ui.test.ts`, `tests/placement.test.ts`).
- Ribbon buttons are wired by a single delegated click handler over `data-action`/`data-theme-id`; the drawing tools use `data-tool`; built-in topologies load from the File-tab `<select>`, and scenarios from the `#scenarioMenu` flyout. Tab switching lives in [ribbon.ts](ribbon.md).
