# `src/engine.ts` — The simulation engine

The largest and most important module. Drives a ping/DHCP simulation through two phases — **process** (dequeue an event, run the per-device handler, collect outgoing frames) and **animate** (interpolate transit dots, deliver on arrival) — and implements per-device packet processing, routing, and RIP.

## Public API (lifecycle)
- **`startSimulation(setup, sourceId, targetIp, mode?)`** — seeds the queue from a `PingSetup`/DHCP setup and starts the rAF animation loop. The setup's first event (an arrive at the first hop) is seeded as a **transit** rather than an arrive event, so the opening frame animates *off the source* — otherwise it would appear to originate at the connected switch/router (every later hop already animates because a completed transit creates the next arrive event). The headless runner keeps draining events directly.
- **`stopSimulation`, `pauseSimulation`, `resumeSimulation`, `stepOnce`** — sim controls (wired to the on-canvas play/pause/step buttons).
- **`syncSimLog()`** — rebuilds the sim-log dock pane: the Wireshark-style **packet list** (`renderPacketTable` over the filtered `sim.capture`, columns via `packetColumns` in `frame.ts`) or the narrative **event view** (`renderEventLog` over `sim.log`), per `state.dock.logView`. In the packet view it also syncs the **capture-history controls** (`syncSimLogCaptureBar` — which saved run to view + the compare toggle/baseline, shown only when idle with ≥1 archived run) and the **display-filter toolbar** (`syncSimLogFilterBar`): the protocol chips (class-toggled, dimmed when absent from the capture), the device `<select>` (rebuilt from the devices present in the capture), the expression input (with an `invalid` marker on a parse error), and the "Showing N of M" / error status. The filter itself lives in [packet-filter.ts](packet-filter.md) (`applyLogFilter`); see also the **Packet capture** section below.
- **`startNetworkBoot()` / `unconfiguredBootableHosts()`** — network boot: adding/cabling/powering a host no longer configures it (it stays "unassigned"). When the user starts the sim — **Play** while idle calls `startNetworkBoot()` — every unconfigured, cabled, powered-on host (`unconfiguredBootableHosts`) boots with an **animated** DHCP exchange in turn (a `bootQueue` chained through `finishSimulation`), self-assigning **APIPA** (`169.254.x.y/16`) only after the simulated DHCP times out. The `dhcp` command boots one host the same way. Two **independent** global toggles gate this (`state.options.autoDhcp`/`apipaFallback`, in the **Settings** pane opened by the Main-tab cog button, both **off by default**): auto-DHCP on → animated DHCP, with `finishSimulation` self-assigning APIPA on timeout only if APIPA is on; auto-DHCP **off but APIPA on** → `bootNextHost` skips the DHCP frames and calls `assignApipa` directly (instant, no run); both off → `startNetworkBoot` boots nothing. `assignApipa(device)` is the shared link-local self-assign used by both the DHCP-failure fallback and the direct path.
- **`runSimulationHeadless(setup, sourceId, targetIp, mode?)`** — drains the queue synchronously (no rAF, no per-step render/terminal output — it sets `sim.headless`) and returns a `SimResult` (`{ success, ttl, responderIp, timeExceeded, assignedIp, assignedGateway, log, steps }`). Powers the console `run` verb, `window.routesim`, scenario checks, and tests.
- **`runTraceroute(source, target, maxHops?)`** — warms ARP along the path, then sends probes with increasing TTL (1..maxHops) via `runSimulationHeadless`, recording each hop's responder (a router's ICMP Time-Exceeded, or the destination's Echo Reply). Returns a `TracerouteResult`. Backs the `traceroute`/`tracert` command in the PC terminal and console.
- **`launchRedTeam(): boolean`** — the autonomous **Play** trigger for the **Red Team actor**, filtered to **`type === "attacker"`**: when the canvas is idle and a *ready* actor exists (an IP and ≥1 enabled attack), it finds the first one, builds its frames via `buildAttackEvents` (simulation.ts), and `startSimulation(setup, attacker.id, "", "attack")`. A **Kali PC** (`type: "kali"`) is never launched this way — an unconfigured offensive host boots over DHCP like any other host (`hostNeedsBoot` now includes `kali`). Wired into the ui.ts Play handler after `startNetworkBoot`, so Play boots hosts and then, if nothing else is running, fires the attack. See [red-team.md](red-team.md).

> Because `startSimulation` starts a `requestAnimationFrame` loop, it must **not** be called in unit tests with the preload's synchronous rAF stub (infinite recursion). Tests call the `processAt*` handlers (or `runSimulationHeadless`/`runTraceroute`) directly — or, for genuinely animated behaviour, stub rAF to a no-op and pump with `stepOnce()`. See [testing.md](../testing.md).

### Link cost (latency / loss)
A transit dot's crossing time is `sim.speed × latencyFactor`, where **`linkLatencyFactor(link)`** maps the link's `latency` (ms) to a clamped multiplier (10 ms = 1×, range 0.25–20×) baked onto each `ActiveTransit` — so a far/WAN link visibly crawls. A link's **`loss`** (%) probabilistically drops each forwarded frame at transit-creation time, but **only in animated runs** (`!sim.headless`), so headless reachability checks (scenarios, `run`) stay deterministic; `bandwidth` is metadata for the future streams mode.

### Packet capture
During animated delivery, `deliverCompletedTransits` records each wire traversal into `sim.capture` (a `CaptureEntry`: running number, step, frame, endpoint devices, link — capped at 1000). This is the packet list the sim-log pane renders. Headless runs neither record nor clear the capture, so background boot chatter and scenario checks never wipe a visible packet list; `startSimulation`/`stopSimulation` do clear it.

### Display filtering
The packet list is **filterable** (`state.dock.logFilter`, a `LogFilter` of three ANDed dimensions). `syncSimLog` enriches each `CaptureEntry` into a `FilterRow` (`buildFilterRows` — the frame plus its wire endpoints) and runs `applyLogFilter` ([packet-filter.ts](packet-filter.md)) before `renderPacketTable`, so only matching frames are drawn while the underlying capture is untouched (clearing the filter shows them all again). The compiled expression predicate is cached by its source text, so re-filtering on every animation step is cheap. The filter is a *view* preference — it survives across runs (Wireshark keeps the display filter), but a deleted device referenced by the device dimension falls back to "All".

### Capture history (multi-run compare)
Each finished animated run is archived to `state.savedCaptures` (a `SavedCapture` ring, cap 12) by `saveCurrentCapture` in `finishSimulation`, with a derived label (`captureLabel` — mode + endpoints + ✓/✗) and a monotonic id (`cap-<index>`). `state.dock.captureView` selects which capture the packet list shows ("live" while a run animates, else a saved id), and `state.dock.compareBaseId` ("" = off) names a baseline shown **side by side** on the left in compare mode. `displayedPanes()` resolves these to the 1-or-2 panes `syncSimLog` renders; the device dropdown and chip-dimming span every displayed pane. Rows carry `data-cap` so a click resolves against the right capture (`captureEntriesFor`), and the selected-row highlight is scoped by entry identity (capture numbers restart per run). Starting a run points the view at "live"; stopping falls it back to the most recent saved run; loading a topology clears the history (the captures reference devices that no longer exist).

## Per-device processing
Each handler takes a device, an incoming frame, and the ingress peer id, and returns `OutgoingFrame[]`:

- **`processAtComputer`** — answers ARP for its own IP, replies to ICMP echo requests, marks ping success on echo reply, drives the DHCP client (Discover→Offer→Request→Ack, assigning IP/gateway/prefix and learning the router MAC on Ack), and speaks **TCP**: a SYN to a listening port (no `openPorts` list = listen on all; otherwise only those) answers SYN-ACK, a closed port answers RST, and the origin completes the handshake with ACK (`sim.tcpSuccess`).
- **`processAtSwitch`** — MAC-learns on ingress, then forwards (known unicast) or floods (broadcast/unknown). Managed switches enforce 802.1Q VLANs: access ports tag/untag, trunk ports carry allowed VLANs with a native VLAN. A `bpdu` frame early-returns to `handleBpdu` (like `dot11`/`dot1x`). When a managed switch carries a SPAN session (`SwitchConfig.mirror = { name, dest, sources? }`), the **monitor (`dest`) port is excluded from normal forwarding** and each ingress frame matching the session is **copied** to the monitor port's peer (`id` suffixed `-span`) — feeding a cabled IDS. Control frames terminated earlier (BPDU/dot11/dot1x) aren't mirrored (a documented simplification). See [ids.md](ids.md).
- **`processAtRouter`** — matches the ingress interface by peer, then dispatches: ARP → `handleRouterArp`, broadcast DHCP → `handleRouterDhcp` (allocates a lease, sends Offer/Ack), otherwise → `routeIpv4Frame`. Routing checks TTL **before** the forwarding decision (so an expired packet to an unrouteable destination still replies): on TTL 0 it drops the packet and sends an **ICMP Time-Exceeded** back from the ingress interface (the traceroute signal); otherwise it decrements TTL, rewrites L2 headers, and ARP-resolves on egress (buffering the frame in `pendingArp` on a miss). The self-IP branch answers ICMP echo to the router's own interface IP — and narrows on `payload.type === "icmp"` so a DHCP packet addressed to the router IP isn't mistaken for a self-ping.

`processAtRouter` is decomposed into `handleRouterArp` / `handleRouterDhcp` / `routeIpv4Frame` for clarity; the orchestrator just matches the ingress interface and dispatches. When interfaces carry `ip nat inside`/`outside` marks, `routeIpv4Frame` also translates inside→outside flows and restores the return path (see [nat.md](nat.md)); the router's own **stateful** netfilter INPUT (traffic to the router) and FORWARD (routed traffic) chains filter before delivery/forwarding — each classifying the frame's connection state, tracking accepted flows, and answering a REJECT with an RST/ICMP-unreachable, like the firewall device. The un-NAT happens before the FORWARD chain, so conntrack sees consistent tuples. See [firewall.md](firewall.md).

- **`processAtServer`** — answers DNS queries from its A-records (a `DnsPayload` response; unknown name → NXDOMAIN) and serves DHCP from its configured `dhcp-range` (`handleServerDhcp`, with router + nameserver options), both gated on `dnsmasqRunning`; everything else falls through to `processAtComputer`, so a server is also an ordinary host endpoint. See [dns.md](dns.md).

- **`processAtHub`** — a layer-1 repeater (the **Legacy** device class): copies every incoming frame out all other ports, with no MAC learning and no forwarding logic — the dumb predecessor to a switch (one collision domain; floods unicast too, which is the teaching contrast with a switch).
- **`processAtFirewall`** — a transparent inline packet filter: bridges ARP/control frames to the other port(s) and evaluates each IPv4 packet against the FORWARD chain. It first classifies the frame's connection state via `connectionState(device, ipv4)` — `"new"` (no matching conntrack entry) or `"established"` (the reply of a flow we already let out, matched on the swapped 5-tuple, or a later packet of one) — then runs `evaluateFirewall(device, ipv4, "FORWARD", conn)` (first-match-wins, else the chain policy) over `firewallRuleMatches(rule, ipv4, conn)` (src/dst CIDR, protocol, ICMP type, TCP dport, **connection state**). On ACCEPT it forwards and calls `trackConnection(device, ipv4)` to record the flow; on REJECT it emits a response via `rejectResponse` (a TCP RST for a TCP segment, else an ICMP destination-unreachable) rather than dropping silently; DROP discards. Logged with the state, e.g. `Firewall DROP … (FORWARD, new)`. Conntrack only runs when a rule uses `-m state` (`firewallUsesConntrack`), so a stateless ruleset has no per-frame cost; `related`/`invalid` parse but are never assigned. See [firewall.md](firewall.md).
- **`processAtIds`** — a passive Snort sensor: a **sink**, never in the data path. It runs the rule set (`config.idsRules`) against the mirrored frame via `runIdsRules` (`snort.ts`), appends any fast-alert line to `config.alerts` (capped, runtime-only — not serialised), logs a `sim-ids` line, and returns **no** outgoing frames — so it **alerts but never drops**. Fed the SPAN copy from `processAtSwitch`. See [ids.md](ids.md).
- **`processAtAttacker`** — the shared **Kali-Linux attack handler** for both offensive host types: the hand-driven **Kali PC** (`type: "kali"`) and the autonomous **Red Team actor** (`type: "attacker"`). For ordinary host behaviour it delegates to `processAtComputer`; the extra logic only fires during a sim in mode `"attack"`, where the offensive host is the run origin, on replies addressed to it: a **SYN-ACK** records an open port (`sim.scanOpen.push(srcPort)` + a `sim-attack` log), a **RST** records a closed one (`sim.scanClosed`), and an **ICMP echo reply** (`icmpType 0`) marks a live host (`sim.sweepLive`). The scan is **half-open** — it never completes the handshake with an ACK. Registered in the `PROCESSORS` map for **both** `attacker` and `kali`, so a hand-run Kali PC scan tallies too. See [red-team.md](red-team.md).

## Routing & RIP
- **`buildRoutingTable(router)`**, **`routingLookup`**, **`runRipConvergence`** now live in **`src/routing.ts`** (re-exported here for compatibility): the table merges connected (metric 0), static (metric 1), and RIP-learned (metric 2+) routes; the lookup resolves a destination to an egress interface. `routingLookup(router, dst, prebuilt?)` accepts an already-built table so a caller resolving several frames for one router in a single pass (an ARP reply flushing buffered frames) builds the table once instead of per frame.
- **`runRipConvergence()`** — runs automatically before each simulation. Iterates up to 15 rounds exchanging advertisements between RIP-enabled routers until no route changes. Implements split-horizon (don't advertise a route back out the interface it was learned on) and metric 16 = unreachable. Decomposed into advertisement-building and update-applying helpers. Router interface normalisation is **memoised per run** for performance, and the whole thing is benchmarked.

## Spanning tree (STP)
- **`runStpConvergence()`** (in **`src/stp.ts`**, re-exported here) — runs automatically before each simulation, right after `runRipConvergence()` (both `startSimulation` and `runSimulationHeadless`). Computes the spanning tree across managed switches and mutates `config` in place (like `runRipConvergence`), electing a root per connected component and marking each alternate port's link `link.stpBlocked`. The blocked flag folds into `linkAuthorizedForData(link)` (devices.ts) alongside WiFi/802.1X/MACsec, so the three chokepoints (`l2Reachable`/`findFirstHop`/the engine transit step) drop **data** on a blocked link; the transit step's control-frame `ctrl` set now includes `"bpdu"`, so BPDUs (alongside `dot11`/`dot1x`) bypass the gate. See [stp.md](stp.md) for the model.
- **`handleBpdu`** — relays a Configuration BPDU arriving on a bridge's root port out its designated ports (root cost + 1), toward other switches only; it terminates (never loops). `processAtSwitch` early-returns here for `bpdu` frames. `buildStpEvents` (simulation.ts) seeds the flood from each root bridge's designated ports for the animated `stp`/headless `run stp` mode.
- **Broadcast storm** — with STP off and an L2 loop, frames multiply without bound. The headless path caps via `MAX_STEPS=10000`; the animated path caps via `STORM_STEP_CAP=200` / `STORM_TRANSIT_CAP=250`. Either sets `sim.stormDetected`, surfaced by `finishSimulation` ("Broadcast storm…") and the status line. The `silentStp` display option hides BPDU animation like the other silent protocols.

## Red Team (attack mode)
- **`SimulationState.mode`** gains **`"attack"`**, and `SimulationState` gains the scan accumulators **`scanOpen: number[]`**, **`scanClosed: number[]`**, and **`sweepLive: string[]`** — all cleared at each run start, as is every offensive host's `attackLog` (both `attacker` and `kali`). `processAtAttacker` fills them (see above); `SimResult.success` for an attack is `scanOpen.length > 0 || sweepLive.length > 0`.
- **`SERVICE_NAMES`** maps a port to its service name (e.g. 21:ftp, 22:ssh, 23:telnet, 80:http, 443:https, 3306:mysql, 3389:rdp) for the report.
- **`finishSimulation`'s `"attack"` branch** builds an **nmap-style report**: a `PORT  STATE  SERVICE` table of the open ports (named via `SERVICE_NAMES`) plus a `Hosts up: N (...)` line for a sweep, falling back to "No open ports or live hosts found". It writes the report to the origin's terminal session **and** stashes it on `origin.config.attackLog` for the inspector.
- The attack frame builders (`buildScanEvents`/`buildSweepEvents`/`buildArpSpoofEvents`/`buildAttackEvents`) live in `simulation.ts` and are documented there and in [red-team.md](red-team.md); `launchRedTeam` (above) is the engine-side **Play** trigger that runs them. See [red-team.md](red-team.md) for the full attacker model.

## How it fits

`engine.ts` sits at the centre of the simulation: it consumes `simulation.ts`'s event setup, creates response frames via `frame.ts`, reads/writes device config (ARP/MAC/DHCP tables) on `state`, and calls `sync().render()`/`syncSimLog()` to animate. Forwarding decisions reuse `devices.ts` (interface enumeration) and `simulation.ts`/`utils.ts` (subnet maths).
